# Specification deltas

The unmodified operator specification is preserved in [SPEC.md](SPEC.md). These entries describe intentional departures for the baseline; the operator decides whether to merge changes into the original specification.

- **Spec §2 and §4, anti-detection stack:** The baseline uses a central fetch router with per-domain budgets, robots rules, cache, and block pauses. It does not use proxy rotation, login sessions, stored cookies, challenge solving, or stealth browsing. The optional Scrapling Tier 1 fetcher is HTTP-only; Tier 3 remains disabled by default.
- **Spec §3 and §10, contact discovery:** Maigret, Social Analyzer, FORGE, broad people-search sites, and breach sources are excluded. Person discovery uses bounded public ATS/HN data, replayable search snippets, and public-page links; it never fetches LinkedIn result pages.
- **Spec §2 and §3, outreach:** The baseline has no email-sending path. It produces review data and draft files for a person to send manually, rather than implementing a send action with per-message approval.
- **Spec §8, data handling:** Evidence is tagged with a professional-use flag and retained ephemerally with explicit purge support, as required by the plan.
- **Spec §5, candidate model:** `EmailCandidate` includes the plan's `evidence_tier` (`A`, `B`, or `C`) field so scoring and outreach eligibility can preserve evidence quality alongside the spec's provenance fields.
- **Operator platform decision:** LinkedIn, Indeed, and Glassdoor are enabled only under the operator's explicit logged-out policy: 30–90 second spacing, 10 requests per day, Tier 1 maximum, no cookies or credentials, no challenge solving or stealth, and a 48-hour pause after a block. Indeed and Glassdoor are for job/hiring signals; LinkedIn page fetches are allowed only on a search-snippet miss and are never bulk crawled.
- **SMTP identity:** SMTP checks stop until `LEADFORGE_SMTP_MAIL_FROM` is a syntactically valid, non-placeholder address; the operator must control its domain. This prevents checks from running with the sample identity.
- **DNS errors:** NXDOMAIN, null MX, and empty MX answers can produce `kill`; resolver timeouts and other resolver failures produce `unknown`/`pattern_only` with a 0.40 confidence cap. The optional `dns_nameservers` override defaults to the system resolver.
- **Discovery sources:** ATS and Hacker News adapters route live fetches through the shared policy router. People search supports replay and local SearxNG. The approved DuckDuckGo response snapshot is used by its parser; no other live search was run by the agent.
- **Company seeding:** `seed-companies` follows the operator's ordered source list and requires a resolving official domain plus a homepage-name check. Existing HN, ATS, and approved DDG parsers are used for their available structured formats. YC, Work at a Startup, Wellfound, LinkedIn, Glassdoor, and Indeed return unrecognised until their actual page markup is available; no guessed card selectors are enabled. A run with fewer than 8 accepted companies stops; 8–14 is the documented fallback. It writes `companies.csv`, metadata, matching jobs, and count-only source statistics.
- **Run summary:** `export-run-summary` exports aggregate source and stage metrics only. The JSON has fixed source/stage labels and numeric fields; it omits person/company identifiers, email addresses, URLs, and page text.
- **Markup validation limitation:** The specified `data/cache/leadforge.db` contained no `page` rows during this implementation. Consequently, no YC, Work at a Startup, or job-platform markup was available to parse; these sources remain unrecognised-only until a cache sample is present. The first operator live run should save source pages and confirm their structures before interpreting a zero-yield source as having no listings.
